## Goal
Add an optional `purpose_code` to `TransactionIn` for `POST /transactions/screen` (exactly 4 uppercase letters, e.g. `SALA`) and reject malformed values with the existing validation status code. Issue #84.

## Files to change
- `app/models.py`
- `tests/test_transactions.py`

## Steps
1. Add `purpose_code: str | None` with a `^[A-Z]{4}$` pattern to `TransactionIn`, next to the other pattern-validated fields.
2. Add tests: valid code accepted, omitted code accepted, malformed codes rejected.
3. Run the full suite with the command in AGENTS.md.

## Tests to add
- `test_screen_accepts_purpose_code`
- `test_screen_rejects_malformed_purpose_code`

## Success criteria
- Valid and omitted `purpose_code` → 201; malformed → 422 (FastAPI's default, same as the other fields).
- CI passes with `uv run pytest -v`.

## Out of scope
- Screening rules, thresholds and scores (`app/rules.py`, `app/screening.py`), `infra/`, docs and README.

## Rollback / escalation
- Revert the implementation PR; no data migration.
